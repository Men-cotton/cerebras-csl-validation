# Full CSL GNN training validation

Each named case fixes normalized inputs, supervised targets, initial weights, graph ownership, CSL sources and independently computed expected predictions, gradients and SGD updates. The appliance worker supplies frames and invokes the compiled kernel; it computes no gradients or optimizer updates. The worker and appliance collector admit completed SDK calls and complete, hash-bound captures. Their PASS means execution and collection succeeded; numerical_status remains NOT_RUN. The local NumPy auditor compares every prediction, parameter gradient and updated parameter, plus input readbacks, exact SDK calls, all operation counters, lifecycle and local clocks.

`appliance.py compile --case NAME --backend hardware --namespace job-operator --out OUT` submits one compiler operation. `appliance.py run --case NAME --backend hardware --artifact-record BUILD/training-build.json --host-timeout 300 --out OUT` submits one runtime. Outputs must be fresh. Both actions record job IDs through SDK logging and retain failed states. The request template bounds each client action to 1200 seconds; the worker has a separate 300-second timeout and 15-second termination grace. A client timeout does not establish remote termination.

Case admission is bounded to 128 MiB; capture admission to 256 MiB and 256 regular entries. Download sizes are checked after transfer; these are admission limits, not live remote disk quotas. Captures include frozen case/host source, compiled ABI metadata and all raw arrays. Compiler artifacts and caller outputs stay outside the source tree. No retry or campaign loop exists here.

## Local numerical verification

After collection, run `uv run --locked --group dev python validations/csl-training/saved_audit.py CAPTURE --out numerical-report.json` from the validation repository root. CAPTURE is either the extracted `capture-data/` directory or the downloaded `capture` tar archive. The report path must be fresh. Exit codes are 0 for numerical PASS, 1 for numerical FAIL with complete execution, and 2 for incomplete or corrupt capture. Existing worker records are never rewritten. Complete legacy captures whose worker failed during numerical audit can be replayed locally; the report retains their original status and error. The numerical tolerances remain rtol=0.0008 and atol=0.00008.

Numerical PASS after H4/S2 and a few SGD steps establishes a numerical training primitive only. They do not establish converged fluid accuracy, Adam training, native H128/S15 admission, or an end-to-end speedup. `request-template.json` is a draft: follow the parent request contract to publish it with a new execution ID and explicit request trailers. No job was submitted by export.
