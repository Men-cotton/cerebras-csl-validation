Do not reinitialize its ledger or synchronize the SDK environment.


The controller checks all recorded PIDs and jobs and its own active jobs in the
configured namespace. A missing/pruned job record is not proof of termination.

```bash

  --config "$HOME/csl-operator.json" \

```

The old request becomes `interrupted`; its completed steps and evidence are
preserved. Accumulated2GiB output is advisory in the repaired controller. If ZIP

retries packaging only. The4GiB collector ceiling remains. Do not mark the old
request passed or manually advance its step counter.

## Restart and observe

Use a fresh named tmux session; the previously observed session `0` can remain
for other shells. The command pins the controller directory and clears inherited
SDK-environment overrides.

```bash
printf -v CSL_WATCH_COMMAND '%q ' \
  env -u UV_PROJECT_ENVIRONMENT "$(command -v uv)" --directory "$PWD" run --locked \
  -m csl_validation watch run --config "$HOME/csl-operator.json"
tmux new-session -d -s csl-validation "$CSL_WATCH_COMMAND"
pgrep -af '[c]sl_validation watch run'
tmux capture-pane -p -t csl-validation -S -80
uv run --locked -m csl_validation watch status --config "$HOME/csl-operator.json"
```

The previously published halo-shape request may precede both new requests.
The watcher processes the queue serially. If a step blocks, inspect its receipt
and job state before further action. `watch once` is not a dry run. Results are
collected through the existing fetch workflow; a pending request or a live
watcher is not proof that a hardware job is already running.
